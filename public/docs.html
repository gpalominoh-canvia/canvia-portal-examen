Referencia de la API · v1

API del Portal Canvia Market

API REST en JSON para gestionar el catálogo de productos y los pedidos de los clientes de Canvia Market. Es la misma API que consume la tienda web.

ElementoValor
URL basehttp://localhost:3000 (o la que expone la action en la CI)
Prefijo/api
FormatoJSON en UTF-8. Envía Content-Type: application/json en las peticiones con cuerpo.
MontosSoles (PEN), número con hasta 2 decimales.
FechasISO 8601 en UTC, por ejemplo 2026-10-30T15:04:05.000Z.
PersistenciaEn memoria. Se pierde al reiniciar el servidor y se restaura con POST /api/reset.

Autenticación

Las operaciones de escritura sobre productos y todas las operaciones de pedidos exigen un token Bearer. Obtén el token con POST /api/auth y envíalo en cada petición:

Authorization: Bearer 3f9c2a...e81b

El token no expira mientras el servidor esté encendido. Cada inicio de sesión genera un token nuevo; los anteriores siguen siendo válidos.

Errores y códigos de estado

Toda respuesta de error tiene el mismo formato:

{ "error": "Producto no encontrado" }
CódigoSignificado
200Operación correcta.
201Recurso creado. Incluye la cabecera Location.
204Operación correcta sin cuerpo de respuesta.
400Datos inválidos, JSON mal formado o regla de negocio incumplida.
401Credenciales incorrectas, o token ausente o inválido.
404El recurso no existe o no pertenece al usuario.
405Método no permitido en la ruta (ver cabecera Allow).
423Usuario bloqueado.
500Error no controlado del servidor. No debería ocurrir nunca.

Usuarios de prueba

Todos usan la clave canvia123.

UsuarioComportamiento
anaCliente habitual. Úsalo para los flujos principales.
bloqueadoCuenta bloqueada: POST /api/auth responde 423.
lentoSimula una red lenta: cada respuesta tarda unos 1,5 segundos.
erroresCliente que usa una versión anterior de la tienda web.
GET/api/saludPúblico

Indica si el servicio está disponible. Úsalo para esperar a que el portal levante.

Ejemplo
curl http://localhost:3000/api/salud { "estado": "ok", "servicio": "Portal Canvia Market", "version": "1.0.0" }
200 disponible
POST/api/resetPúblico

Restaura el catálogo inicial (12 productos, ids 1 a 12) y elimina todos los pedidos. Los tokens emitidos siguen siendo válidos. Los ids nuevos vuelven a empezar en 13 (productos) y 1001 (pedidos).

curl -X POST http://localhost:3000/api/reset { "estado": "ok", "mensaje": "Datos iniciales restaurados" }
200 datos restaurados
POST/api/authPúblico

Inicia sesión y devuelve el token para las siguientes peticiones.

CampoTipoRegla
usuariotextoObligatorio. No distingue mayúsculas.
clavetextoObligatorio.
Ejemplo
curl -X POST http://localhost:3000/api/auth \ -H "Content-Type: application/json" \ -d '{"usuario":"ana","clave":"canvia123"}' { "token": "9b1f0c4e7a...d2", "tipo": "Bearer", "usuario": "ana", "nombre": "Ana Torres", "interfaz": "2.4" }
200 token emitido 400 faltan usuario o clave 401 usuario o clave incorrectos 423 usuario bloqueado
GET/api/productosPúblico

Lista los productos activos. Ambos filtros son opcionales y se pueden combinar.

ParámetroDescripción
buscarTexto contenido en el nombre. No distingue mayúsculas ni tildes.
categoriaNombre exacto de la categoría (sin distinguir mayúsculas ni tildes).
Ejemplo
curl "http://localhost:3000/api/productos?buscar=teclado&categoria=Accesorios" [ { "id": 7, "nombre": "Teclado numérico USB", "descripcion": "Teclado numérico compacto para hojas de cálculo.", "precio": 69.9, "categoria": "Accesorios", "stock": 60 } ]
200 lista (puede ser vacía)
GET/api/productos/:idPúblico

Devuelve un producto por su id.

curl http://localhost:3000/api/productos/3
200 producto404 no existe
POST/api/productosRequiere token

Crea un producto. Devuelve el producto creado con su id y la cabecera Location.

CampoTipoRegla
nombretextoObligatorio, de 1 a 80 caracteres.
precionúmeroObligatorio, mayor a 0. Se redondea a 2 decimales.
categoriatextoObligatorio. Una de: Tecnología, Accesorios, Oficina, Hogar.
stockenteroOpcional, mayor o igual a 0. Por defecto 0.
descripciontextoOpcional.
Ejemplo
curl -X POST http://localhost:3000/api/productos \ -H "Authorization: Bearer $TOKEN" \ -H "Content-Type: application/json" \ -d '{"nombre":"Webcam Full HD","precio":219.9,"categoria":"Accesorios","stock":30}' { "id": 13, "nombre": "Webcam Full HD", "descripcion": "", "precio": 219.9, "categoria": "Accesorios", "stock": 30 }
201 creado 400 validación 401 sin token
PUT/api/productos/:idRequiere token

Reemplaza todos los datos del producto. Exige el mismo cuerpo y las mismas reglas que la creación.

curl -X PUT http://localhost:3000/api/productos/13 \ -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \ -d '{"nombre":"Webcam 4K","precio":399,"categoria":"Accesorios","stock":10}'
200 producto actualizado 400 validación 401 sin token 404 no existe
PATCH/api/productos/:idRequiere token

Modifica solo los campos enviados. Cada campo enviado sigue las reglas de la creación. Un cuerpo vacío responde 400.

curl -X PATCH http://localhost:3000/api/productos/13 \ -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \ -d '{"precio":199.9}'
200 producto actualizado 400 validación 401 sin token 404 no existe
DELETE/api/productos/:idRequiere token

Elimina el producto del catálogo. Después de eliminarlo, GET /api/productos/:id responde 404 y el producto deja de aparecer en el listado.

curl -X DELETE http://localhost:3000/api/productos/13 -H "Authorization: Bearer $TOKEN"
204 eliminado 401 sin token 404 no existe
GET/api/categoriasPúblico

Lista de categorías válidas.

curl http://localhost:3000/api/categorias ["Tecnología", "Accesorios", "Oficina", "Hogar"]
200 lista
GET/api/pedidosRequiere token

Lista los pedidos del usuario autenticado, incluidos los cancelados. Nunca devuelve pedidos de otros usuarios.

curl http://localhost:3000/api/pedidos -H "Authorization: Bearer $TOKEN"
200 lista401 sin token
POST/api/pedidosRequiere token

Registra un pedido del usuario autenticado. El pedido nace en estado pendiente. El stock no se descuenta.

CampoTipoRegla
itemslistaObligatorio, al menos un ítem.
items[].productoIdenteroId de un producto existente.
items[].cantidadenteroMayor o igual a 1 y no mayor al stock del producto.
envioobjetoOpcional: { "nombre", "direccion" }. Lo envía la tienda web.
Ejemplo
curl -X POST http://localhost:3000/api/pedidos \ -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \ -d '{"items":[{"productoId":4,"cantidad":2},{"productoId":10,"cantidad":1}]}' { "id": 1001, "usuario": "ana", "items": [ { "productoId": 4, "nombre": "Mouse ergonómico vertical", "precioUnitario": 129.9, "cantidad": 2, "subtotal": 259.8 }, { "productoId": 10, "nombre": "Lámpara LED de escritorio", "precioUnitario": 89.9, "cantidad": 1, "subtotal": 89.9 } ], "subtotal": 349.7, "descuento": 0, "total": 349.7, "estado": "pendiente", "envio": null, "fecha": "2026-10-30T15:04:05.000Z" }
201 creado 400 validación o stock insuficiente 401 sin token
GET/api/pedidos/:idRequiere token

Devuelve un pedido del usuario autenticado. Si el pedido no existe o pertenece a otro usuario, responde 404.

curl http://localhost:3000/api/pedidos/1001 -H "Authorization: Bearer $TOKEN"
200 pedido401 sin token404 no existe o es ajeno
PATCH/api/pedidos/:idRequiere token

Avanza el estado del pedido. Solo se permite avanzar un paso: pendiente → pagado → enviado. Cualquier otra transición (retroceder, saltar un paso o cambiar un pedido enviado o cancelado) responde 400.

curl -X PATCH http://localhost:3000/api/pedidos/1001 \ -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \ -d '{"estado":"pagado"}'
200 pedido actualizado 400 estado o transición inválida 401 sin token 404 no existe o es ajeno
DELETE/api/pedidos/:idRequiere token

Cancela el pedido: su estado pasa a cancelado y sigue apareciendo en el historial. Un pedido enviado no se puede cancelar.

curl -X DELETE http://localhost:3000/api/pedidos/1001 -H "Authorization: Bearer $TOKEN"
204 cancelado 400 pedido ya enviado 401 sin token 404 no existe o es ajeno

Reglas de negocio

  • Precio: todo producto debe tener precio mayor a 0, tanto al crearlo como al modificarlo.
  • Cantidad: cada ítem de un pedido debe tener al menos 1 unidad y no superar el stock del producto.
  • Descuento mayorista: cada ítem con 5 unidades o más tiene un 10 % de descuento sobre el subtotal de ese ítem. Los demás ítems del pedido se cobran a precio normal. Los importes se redondean a 2 decimales.
  • Estados: pendiente → pagado → enviado, de a un paso. DELETE cancela pedidos pendientes o pagados.
  • Privacidad: un usuario solo puede ver, modificar o cancelar sus propios pedidos.
Ejemplo de descuento mayorista. 6 lámparas (S/ 89.90) y 1 cafetera (S/ 259.00): subtotal S/ 798.40; descuento 10 % de S/ 539.40 = S/ 53.94; total S/ 744.46.
